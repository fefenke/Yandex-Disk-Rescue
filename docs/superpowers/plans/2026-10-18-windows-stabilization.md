# Windows Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Исправить найденные дефекты и оставить один API-способ загрузки без потери совместимости пользовательских данных.

**Architecture:** Сначала независимые исправления на Framework. Затем Engine становится API-фасадом, а политика режимов очищается от старых ветвей. Пользовательские форматы не переписываются; .NET 10 и полная архитектурная переработка отложены.

**Tech Stack:** C# 5, WinForms, .NET Framework 4.7.1, PowerShell, x64/x86.

**Spec:** `docs/superpowers/specs/2026-10-18-windows-stabilization-design.md`.

**Approval:** Пользователь подтвердил план 18 октября 2026. Повторное согласование плана не требуется.

**Execution preferences:** Максимальное качество с экономией токенов; Fast/Ultrafast не включать. Основную работу выполнять последовательно, избегать повторного чтения неизменённых файлов и передачи всей истории помощникам. Модель основной сессии выбирается пользователем в клиенте. Выбор модели и reasoning дочернего агента технически доступен, но текущий инструмент показывает только service tier `priority` и не предоставляет параметр Standard; не запускать помощника без подтверждённого соответствия запрету Fast. Независимый финальный обзор остаётся необходимым и требует совместимого режима запуска; собственную проверку не выдавать за независимую.

## Global Constraints

- Windows 10 1709+ / Windows 11; .NET Framework 4.7.1; x64/x86.
- Не изменять пользовательскую установку, data и папку реальных скачиваний.
- Не публиковать релиз, не изменять опубликованные assets и теги.
- Сохранить JSON-совместимость, DPAPI CurrentUser, защиту путей, хешей и контрольных точек.
- Не добавлять БД, новый UI, новый runtime или зависимости ради этой серии.
- Внести правки на `work/windows-stabilization` в отдельном клоне `audit-yandex-disk-rescue`.

## Review Focus

- Отмена между проверкой файла и записью intent не должна терять исходник: тест задачи 3.
- Новые облачные имена не должны переназначать существующие скачивания: тест задачи 4.
- Повреждённый settings.json не должен затирать корректную резервную копию: тест задачи 2.
- История ошибки прошлой облачной версии не должна выбирать новую версию в DownloadErrors: тест задачи 5.
- Старый клиентский журнал и неизвестные режимы должны оставаться читаемыми без запуска клиента: тест задачи 6.

## Следующий этап, не включённый в эту реализацию

Измерения больших каталогов, изменение формата инвентаризации, полноценный перенос всех тестов в отдельный проект и .NET 10 — отдельные задачи. Образцы форматов и границы подсистем из этой серии должны уменьшить будущую миграцию. Переход имеет смысл после зелёных проверок этой ветки и до крупных новых возможностей, когда согласована поддержка Windows.
