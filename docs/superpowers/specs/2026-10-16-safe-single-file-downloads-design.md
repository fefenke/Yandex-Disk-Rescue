# Безопасные копии и единый файл докачки

Статус: конкретный проект решения для проверки пользователем; продуктовый код ещё не изменён.
Основа: опубликованная 1.0.4, commit e8fd71fb140f316428f36acf9a34a55e5a4ca68d.
Рабочая ветка: feature/safe-single-file-downloads. Публикация новой версии не входит в эту задачу.

## Цель и границы

В API-режиме сохранять существующие и не прошедшие проверку копии без потери данных и бесконечного размножения. Новые диапазоны скачивать сразу в один временный файл, сохраняя карту подтверждённых участков. Переносить пригодные старые части без повторного получения из сети.

Сохраняются C# 5, .NET Framework 4.7.1+, Windows x64/x86, общий лимит соединений, ограничитель API, очередь повторов и контрольные точки 32 МиБ / 15 секунд на поток. Работающий экземпляр и его data не изменяются. Перенос файлов НЕ применяется к режиму официального клиента: перемещение внутри синхронизируемой папки могло бы изменить облако.

## 1. Проверка файла

Проверяем размер первым. При несовпадении не читаем весь файл ради хеша. При совпадении используем облачный MD5; только если MD5 отсутствует — облачный SHA-256. Несовпадение MD5 является ошибкой, а не поводом принять файл по другому алгоритму. Некорректно сформированный хеш в метаданных — ошибка метаданных, а не отсутствие хеша.

SHA-256 запрашивается и сохраняется вместе с размером, modified и MD5. Один выбранный облачный хеш проверяется за один полный проход чтения. Локальные хеши контрольных точек не заменяют облачный хеш всего файла.

Если облачных хешей нет, полное получение файла подтверждается ожидаемой длиной и корректным завершением загрузки; результат обозначается как «Скачан без проверки облачного хеша». Уже существующий файл подходящего размера можно пропустить без дублей, но результат обозначается «Совпал размер; облачного хеша нет». Оба результата не выдаются за криптографическое подтверждение содержимого.

Уровень проверки хранится отдельно от статуса выполнения: проверен сейчас по MD5/SHA-256, использована история прежней проверки, проверен только размер. Старые записи истории не становятся «проверен сейчас» при чтении. Обычный проход использует прежнюю быструю проверку версии/размера/времени записи; «Начать проход с начала» выполняет полную сверку. Дополнительные полные чтения на обычных проходах не добавляются, кроме новой проверки SHA-256 вместо прежнего size-only.

## 2. Существующий файл и новая копия

Обычный файл не используется как префикс докачки только потому, что у него подходящее имя. Докачиваются лишь диапазоны, подтверждённые служебными сведениями и подходящей облачной версией.

Согласованный порядок: сначала скачать новую копию во временный файл и проверить её. До завершения этой попытки прежний обычный файл остаётся на месте. При таймауте, сетевой ошибке или Stop прежний файл не перемещается.

После получения новой полной копии:

| Причина непригодности прежнего файла | Куда сохранить прежний |
| --- | --- |
| Размер не совпал | «Сохранённые прежние файлы» |
| Размер совпал, облачный хеш не совпал | «Файлы с ошибкой проверки» |

Если новая копия прошла выбранную проверку, после сохранения прежней она занимает обычное место. Если её облачный хеш не совпал, новая копия также сохраняется в «Файлы с ошибкой проверки», готовой не считается. Если не удалось сохранить прежний файл, замены нет и новая временная копия сохраняется для восстановления операции. Отсутствие облачного хеша само по себе не является ошибкой совпадения.

Папки сохранения находятся на том же томе внутри назначения; в них сохраняется структура исходных подпапок. Имена копий получают уникальный суффикс с версией/временем и идентификатором операции, без перезаписи одноимённых копий. Путь служебной папки закреплён за контекстом истории и имеет маркер владельца. Если выбранное имя занято чужой папкой, создаётся отдельное имя с суффиксом, чужая папка не присваивается программе. Облачный путь, конфликтующий с уже занятой служебной областью, получает явную ошибку назначения, а не доступ к архиву.

Сохранённые копии автоматически не удаляются. Ошибка создания папки, нехватка места, недоступный файл или обнаруженная точка перенаправления не должны приводить к потере прежнего файла. Перед перемещением повторно сверяются признаки существующего файла; обнаруженное внешнее изменение требует повторной оценки, а не использования устаревшего результата проверки.

## 3. История ошибок, версии и отсутствие дублей

Запись результата привязана к аккаунту, облачному пути, корню назначения и облачной версии: размер, modified, доступные MD5/SHA-256. В ней сохраняются выбранный алгоритм, ожидаемый и полученный хеш, тип проверки, местоположения сохранённых копий и идентификатор операции. Секреты и подписанные ссылки туда не записываются.

После сохранения новой копии с несовпавшим хешем эта облачная версия исключается из автоматических проходов, включая продолжение и повтор проблемных файлов. Пересканирование облака не очищает такую запись. Другой фактический хеш неудачной загрузки не означает новую облачную версию.

Изменённая облачная версия имеет собственную попытку; старые сохранённые копии остаются на месте. В режиме сохранённого списка используются его сведения, в режиме обновления — новый список; дополнительных автоматических обходов всего Диска нет.

Для осознанного повтора добавляется API-режим «Повторить ошибки проверки»: один проход по соответствующим объектам, без автоматического бесконечного повтора этих ошибок. «Начать с начала» не очищает историю ошибок и не является такой командой. При повторном получении той же версии с тем же фактическим хешем и размером существующая сохранённая копия используется как запись результата; ещё одна одинаковая копия не создаётся. Если сохранённая копия отсутствует или была изменена, это не скрывается за дедупликацией.

Для переноса/замены сначала принудительно сохраняется намерение операции с исходными и целевыми путями, версией и отпечатками. Затем выполняются перемещения, после них фиксируются результат и завершение. При запуске незавершённая операция восстанавливается идемпотентно: уже перемещённая копия находится по записи, не забывается и не перемещается повторно. Основная история и журнал операций не должны требовать переписывать весь список после каждого файла.

## 4. Один временный файл и карта

Новый формат: один payload рядом с назначением с суффиксом `.ydr-download`, рядом `.ydr-map` с версией формата и журналом. Готовое имя файл получает только после полного покрытия и выбранной финальной проверки. Отличающийся суффикс позволяет мигрировать старые `.ydr-part`/`.ydr-segments` без одновременной перезаписи источника миграции.

В заголовке карты: контекст, облачная версия, ожидаемая длина и план диапазонов. Запись подтверждения содержит диапазон байтов, последовательный номер и SHA-256 этих байтов. Длина временного файла и выделенные кластеры не являются подтверждением скачивания. Прогресс, выбор очереди докачки и интерфейс используют сумму неперекрывающихся подтверждённых интервалов, а не FileInfo.Length payload.

На поддерживающей sparse-файлы системе используется разрежённый временный файл, чтобы не записывать заранее весь объём нулями. Проверяется поддержка тома, используется обычный Windows FSCTL_SET_SPARSE, без привилегированного SetFileValidData. Если формат не поддерживается, сохраняется прежний безопасный способ отдельных частей; скрытого перехода к дорогому заполнению нулями нет. См. документацию Microsoft: https://learn.microsoft.com/en-us/windows/win32/fileio/sparse-file-operations .

Каждый диапазон имеет отдельный файловый дескриптор и собственную позицию; общей изменяемой Position между потоками нет. Одновременно записываемые диапазоны не пересекаются. Вариант единственной общей очереди записи оставлен для отдельной оптимизации: на этом этапе она не нужна для исключения сборки и усложняет управление сетевыми таймаутами.

Контрольная точка: завершить запись байтов, принудительно сохранить данные payload, затем под блокировкой журнала записать и принудительно сохранить подтверждение карты. Значения 32 МиБ / 15 секунд действуют отдельно на поток и сбрасываются после точки. Локальная запись, очередь диска и flush не расходуют сетевой idle timeout; он действует при ожидании ответа/чтении сетевых данных. Ошибка диска не вызывает сетевые быстрые повторы.

При восстановлении проверяются версия карты, допустимость границ и хеши интервалов. Подтверждённые пригодные интервалы сохраняются; пропуски и повреждённые интервалы скачиваются заново. Оборванная последняя запись не уничтожает предыдущие. Ошибка заголовка/несовместимая версия не допускает признания файла готовым по длине. До начала новых записей карта нормализуется к проверенному набору интервалов. Проверка отменяема и не выполняется под сетевым таймаутом.

Полное покрытие [0, размер) и финальный облачный хеш проверяются перед размещением готовой копии; пустой файл обрабатывается отдельно. При неподдерживаемом Range сначала отменяются и завершаются остальные диапазоны этого файла, затем выполняется однопоточная загрузка с новой картой; нельзя обнулить общий файл, пока другие потоки ещё пишут.

## 5. Старые части

Старый `.ydr-part` и части `.ydr-segments` проверяются по прежнему плану/журналам и свежим сведениям об облачной версии. Подходящие байты копируются в новый `.ydr-download` на свои позиции с подтверждением через новую карту. До сохранения пригодной карты исходные части не удаляются. Прерывание миграции продолжает её по карте, не требует заново скачивать уже перенесённые интервалы и не считает временно скопированные, но неподтверждённые байты готовыми.

Миграция выполняется один раз и требует локального чтения, записи и временного дополнительного места. При нехватке места источники остаются, файл откладывается с понятной ошибкой. Части другой версии не дописываются к новой версии; старые данные сохраняются отдельно, а не удаляются ради начала новой загрузки.

## 6. Проверяемый результат и время

- Тесты MD5-first, SHA-256 fallback, отсутствие обоих, неверный размер и неверный хеш. Совпадение размера без хеша не выдаётся за подтверждение содержимого.
- Старый файл остаётся при прерывании скачивания; все варианты сохранения/замены, блокировки, нехватки места и одинаковых имён не теряют данные.
- Kill между намерением, перемещением, размещением и записью истории не создаёт забытые или повторные архивы.
- Автоповтор и пересканирование не размножают неудачные копии той же облачной версии; новая версия и явный ручной повтор работают отдельно.
- Одновременные записи в один payload с перепутанным порядком поступления дают правильный итоговый MD5/SHA-256. Полная длина при пустой карте не означает готовность.
- Повреждённый участок, оборванная карта, смена версии, Stop, отказ Range и переключение числа потоков сохраняют корректность диапазонов.
- Kill при записи payload, фиксации карты, миграции и финальном размещении проверяется в отдельном процессе. Реальное отключение питания не выдаётся за проведённый тест.
- Проверяются каталог, отчёты, локальная история и интерфейс с разрежённым файлом, неполной картой и старыми записями.
- Полные самопроверки x64/x86 и тесты на HDD E: только в собственной синтетической папке, без пользовательских данных. Доступ к E: для теста выполняется через установленный механизм разрешений.

Экономия нового формата — отсутствие отдельного чтения и записи всего файла для сборки, а также второй полной копии на этапе сборки новых загрузок. Финальная проверка облачного хеша остаётся. Скорость и фрагментация HDD сравниваются со старым форматом на одинаковых данных/потоках; ускорение в процентах заранее не обещается. Единоразовая миграция старых частей и SHA-256 для ранее size-only файлов могут добавить время, это указывается в результате и гайде.

## Самопроверка проекта решения

Порядок «скачать, проверить, сохранить старое, разместить новое» одинаков во всех ветках. Ошибка проверки не превращается в size-only успех. История привязана к облачной версии, а не только к локальному хешу. Ни один неполный payload не признаётся готовым по длине. Перемещение и очистка не касаются папки синхронизируемого клиента. Код и реализация будут спланированы после проверки этого документа пользователем.
