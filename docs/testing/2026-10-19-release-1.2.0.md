# Release 1.2.0 verification — 2026-10-19

Release source: stabilization branch based on 1.1.2, with version `1.2.0.0`, updated RU/EN release notes, download links and embedded guides. Publication was explicitly authorized by the repository owner after the live-account tests.

## Defaults

For a new installation, the initial mode is Remaining. Cloud refresh on manual Start, automatic retries and update checks are enabled. Cloud refresh before every automatic repeat is disabled. Timeouts remain 3 seconds for both link response and download idle, with seven link tasks, 20 download connections and four streams for files of at least 256 MB. The temporary live-test profile is not included.

The UI regression was rebuilt and failed against the previous fresh-install scan default, then passed after enabling manual-start refresh. It checks the mode and checkbox defaults. Existing explicitly saved scan/retry/update settings remain respected; no user data migration or reset is introduced by this release preparation.

## Verified locally

- Sequential x64/x86 compilation and packaging, executable version `1.2.0.0`.
- Full suites via `tests/run-tests.ps1 -OutputDirectory dist/verify-<architecture> -Platform <architecture>`: both PASS, exit code 0 in the ordinary Windows session. Evidence: [x64](release-1.2.0/x64.txt), [x86](release-1.2.0/x86.txt).
- Runner deadline/isolation regressions PASS, including unrelated-process survival and rejection of a stale report.
- Both packaged launchers `--check` PASS on the available Windows build 26200 / Framework release 533509.
- ZIP allowlist contains exactly the ten established distribution paths. No data folder, token vault, personal settings, history, raw reports or runtime logs are shipped. Source Git also excludes those private/generated paths.
- Known production credential/private-key patterns absent from tracked working files and the ten stabilization commits preceding this release commit. This is a pattern check, not proof that arbitrary text can never contain a secret.
- Synthetic report/settings scan from exactly the two final release-suite roots PASS for known credential and signed-link markers. See [result](release-1.2.0/redaction.txt). Existing tests also verify token exclusion from settings JSON and suppression of exception messages in crash diagnostics.
- Embedded guide constants regenerated from the updated guides. The guide change and default change are included in the binaries used by the full suites.

The [live-account report](2026-10-19-live-account-verification.md) records successful download, restart, reuse, hash verification, Stop and resume on the preceding stabilization binary. The version/defaults preparation was followed by the full offline checks above. Unavailable server files are a supported recovery scenario; zero remaining files is not required to pass that live test.

## Publication process

Publish by advancing main without rewriting its history. The existing GitHub Actions workflow builds and tests x64/x86, then the release workflow publishes those verified workflow artifacts under `v1.2.0` with `z-SHA256SUMS.txt`. CI-generated ZIP checksums may differ from local ZIP checksums because packaging metadata is generated again. Publication success must be checked against the remote workflow and release, not inferred from a successful push.

Repository topics cover Yandex Disk, backup/recovery, resumable downloads and the Windows/.NET technologies. No personal account names, cloud paths, file names, credential values or raw live logs are copied into these release reports.

Separate Windows installations/DPI combinations, production self-update installation, physical power loss and large-inventory redesign remain outside the completed verification. .NET migration is deferred.
