Бесплатное приложение для Windows: скачивает доступные файлы с Яндекс Диска, сохраняет историю и повторяет неудачные попытки. Через API с токеном или через официальный клиент без ввода токена.

> [!IMPORTANT]
> **Файлы безлимитной автозагрузки фото и видео НЕ учитываются и НЕ скачиваются.** Поддерживается только обычный раздел **«Файлы»**. Программа не исправляет серверные ошибки и не гарантирует скачивание каждого файла.

## Быстрый старт

Приложение открывает **Настройки**. Кнопки **гайда** и **начала прохода** всегда сверху.

| Через API · по умолчанию | Через официальный клиент |
| --- | --- |
| Получите токен по OAuth-ссылке в приложении и вставьте его в поле | Установите клиент Диска, войдите и дождитесь окончания синхронизации |
| Выберите обычную папку сохранения; `disk:/` — весь Диск, `disk:/Фото` — одна папка | Выберите локальную папку Яндекс Диска на компьютере |
| Клиент не нужен; токен сохраняется через Windows DPAPI | Токен в это приложение вводить не нужно; загрузкой управляет клиент |

Обычно достаточно **сохранённого списка** и режима **«Повторить все нескачанные»**. При первом запуске список создаётся автоматически. Обновляйте его после изменений в облаке, а не перед каждым повтором. Во время работы параметры загрузки заблокированы.

<details>
<summary><strong>Проходы, таймауты и докачка</strong></summary>

- **Продолжить незавершённый** — ещё не обработанные файлы и отменённые попытки.
- **Ошибки сервера / синхронизации** или **таймауты и сбои** — повтор выбранной группы.
- **Все нескачанные** — всё без корректной готовой локальной копии.
- **С нуля** — проверить весь список с начала; готовые файлы повторно не скачиваются.
- **Докачать начатые · API** — только непустые `.ydr-part`.

Автоповтор запускает последующие проходы проблемных файлов с паузой 30 секунд, без обновления списка. В режиме докачки очередь остаётся очередью докачки.

В API два независимых поля: **«Ожидание ссылки»** — ответ после отправки запроса, **«Без данных файла»** — ожидание ответа скачивания и новых байтов. По умолчанию **3 + 3 секунды**, бесконечный бесконечные проходы включены. Очередь и выбранный интервал запуска запросов не расходуют таймауты. До **7 запросов ссылок и 20 скачиваний работают одновременно**. Если включить увеличение, меняется только ожидание данных файла: например, **3, 3, 5** секунд по проходам; новая серия начинает отсчёт заново.

API продолжает временный файл через HTTP Range, если сервер поддерживает продолжение и облачная версия совпадает. Перед завершением проверяются размер и MD5, если он доступен. HTTP 5xx и таймауты — разные причины; IOException не обязательно означает ошибку сервера.

</details>

<details>
<summary><strong>Интерфейс и обновления</strong></summary>

При сверке перед проходом видны количество проверенных файлов, а при проверке MD5 — процент, мегабайты и время. Крупные файлы могут проверяться долго; промежуточный счётчик скачанных ещё не означает итог сверки.

В «Файлах и папках» двойной щелчок открывает готовый файл или содержимое папки. Через правую кнопку можно открыть файл или показать его в Проводнике. Полные имена видны в подсказках; ширину столбцов и панелей можно менять. В журнале есть поиск и фильтры **«Все события / Успешные / Ошибки»**, выделение и прокрутка сохраняются при обновлении статистики. В обзоре скрыты отсутствующие типы файлов.

В настройках можно отключить автоматическую проверку обновлений и пользоваться кнопками **«Проверить обновления» / «Обновить»**. Автопроверка выполняется при запуске и раз в 6 часов; установка — после согласия, когда проход остановлен. ZIP нужной разрядности проверяется по SHA-256 из GitHub, заменяются только файлы программы. Папка `data` с историей, списком, настройками и зашифрованным токеном сохраняется. При ручном обновлении тоже сохраняйте `data` и сначала закройте приложение.

</details>

## Безопасность и помощь

Токен хранится локально через **Windows DPAPI**, с привязкой к учётной записи Windows; при работе расшифровывается в памяти. Это защита хранения, а не гарантия безопасности любого кода. Не публикуйте свою папку `data`, не передавайте токен другим людям и отзывайте доступ, когда он больше не нужен.

[Подробный гайд](https://github.com/fefenke/Yandex-Disk-Rescue/blob/main/GUIDE.md) · [Сообщить об ошибке](https://github.com/fefenke/Yandex-Disk-Rescue/issues) · [Заметки выпуска](https://github.com/fefenke/Yandex-Disk-Rescue/releases/tag/v1.0.3)

К сообщению об ошибке приложите версию, способ скачивания и текст ошибки. Не прикладывайте токены, личные пути или всю историю.

<details>
<summary>Ожидание ссылки и данных · API</summary>

ДВА НЕЗАВИСИМЫХ ТАЙМАУТА В API
«Ожидание ссылки, сек» — сколько ждать ответ API со ссылкой на файл после отправки запроса. По умолчанию 3 секунды. Очередь и выбранный интервал между запусками запросов не расходуют этот таймаут. Если ответ не пришёл вовремя, файл остаётся для следующего прохода.
«Без данных файла, сек» — сколько ждать ответ на скачивание, а затем новую порцию данных. По умолчанию 3 секунды. Отсчёт начинается только при запуске скачивания, сбрасывается при получении заголовков ответа и каждой новой порции данных. Очередь готовых ссылок не расходует это время. Пока данные поступают, файл может скачиваться дольше установленного значения. Короткий предел способен прервать медленную рабочую загрузку. Через официальный клиент это поле задаёт предел отсутствия прогресса получения файла; ожидание ссылки к этому режиму не относится.
Оба поля можно менять от 1 до 60 секунд. Это разные этапы, а не общий бюджет на файл: при 3 + 3 получение ссылки имеет свои 3 секунды после отправки, затем скачивание — свои 3 секунды без данных.

ПАРАЛЛЕЛЬНАЯ РАБОТА
До 7 запросов ссылок и до 20 скачиваний работают одновременно и независимо: пока одни файлы скачиваются, для следующих уже получаются ссылки. Это верхние пределы, а не гарантированное число передач. Готовые ссылки ждут свободного места в ограниченной очереди. Интервал запросов API по умолчанию — 50 мс.
По умолчанию включён бесконечный повтор проблемных файлов с постоянными значениями 3 + 3 секунды, без автоматического увеличения. Стоп отменяет всю серию. Вручную выбранные значения сохраняются. При переходе на новую схему настройки один раз устанавливаются в 3 + 3, бесконечные проходы включены; история, список файлов и токен сохраняются.

</details>

<details>
<summary>Параллельность и подбор настроек</summary>

ПАРАЛЛЕЛЬНОСТЬ: ЧТО МЕНЯЮТ ДВА ПОЛЯ
«Запросов ссылок» — сколько задач одновременно запрашивают у API ссылки на следующие файлы. По умолчанию 7, можно выбрать от 1 до 30. Это количество задач в работе, а не число запросов в секунду. Увеличение помогает, если скачивания простаивают в ожидании ссылок; уменьшение стоит попробовать при росте таймаутов ссылки, сетевых сбоев или ответах 429. Больше запросов не гарантируют больше успешных файлов.
«Скачиваний» — сколько файлов одновременно могут ожидать ответ сервера или получать данные по уже полученным ссылкам. По умолчанию 20, можно выбрать от 1 до 30. Пока часть файлов ждёт сервер, другие могут скачиваться. При таймауте место освобождается для следующего файла. Если готовых ссылок мало, заняты будут не все места.
7 + 20 — оптимальный баланс по нашим тестам и начальная рекомендация, а не лимит Яндекса или универсальный оптимум для любого подключения. Можно поставить 30 + 30. Верхний предел 30 в каждом поле установлен программой для ограничения нагрузки на соединения и память. Очередь остаётся ограниченной и не создаёт задачу на каждый файл сразу.
На медленном интернете попробуйте уменьшить число скачиваний, например до 5–10: файлы делят общую скорость канала, и дополнительные потоки не увеличивают её. Если скорость уже близка к скорости вашего подключения, увеличение количества скачиваний обычно не ускоряет общий результат. Если канал простаивает из-за ожидания ответов, увеличение может помочь. Для крупных файлов несколько передач могут заполнить канал, для множества мелких важнее скорость получения ссылок.
Меняйте один параметр за раз и сравнивайте несколько проходов при одинаковых таймаутах: сколько файлов и данных действительно скачалось и за какое время. Быстрый проход с большим количеством отказов не обязательно лучше. Все пять параметров загрузки сохраняются, во время прохода и пауз автоповтора менять их нельзя. Параллельность и ожидание ссылки относятся только к API; через официальный клиент количеством загрузок управляют Windows и клиент.

ИНТЕРВАЛ ЗАПУСКА ЗАПРОСОВ
«Интервал запросов API, мс» — время между запусками запросов API. Диапазон 25–1000 мс, по умолчанию 50 мс. При 25 мс получается примерно до 40 запусков в секунду, при 50 — до 20, при 100 — до 10, при 200 — до 5, при 1000 — до одного. Ответа предыдущего запроса ждать не нужно: несколько задач могут одновременно ожидать ответ.
Уменьшайте интервал, если хотите повысить частоту запусков и сравнить результат. Увеличивайте, если появляются ограничения частоты, ответы 429 или нестабильность API. Меньший интервал не гарантирует лучшую скорость или успешность. Ожидание очереди и выбранного интервала не расходует таймаут получения ссылки. Значение сохраняется и блокируется во время работы.
В пункте 2.2 официальных условий API Яндекс Диска указан предел 40 запросов в секунду: https://yandex.ru/legal/disk_api/ru/ . Это ограничение частоты, а не числа одновременно ожидающих задач. Начальные 50 мс оставляют запас до указанного предела.

</details>


Крупные файлы через API: по умолчанию 4 потока на файл от 256 МБ. Можно выбрать 1–8 потоков и порог 64–4096 МБ. Все части учитываются в общем лимите соединений скачивания. Недокачанные части сохраняются для следующих проходов; после сборки проверяются размер и MD5. Подробнее — во встроенном гайде.
