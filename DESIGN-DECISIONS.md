# Зачем проект устроен именно так

[Гайд](GUIDE.md) · [Проверки](TESTING.md) · [Исходники](src)

Документ описывает текущую ветку стабилизации Windows: API-движок, единый файл с картой, сохранение прежних копий и возобновление обхода незавершённой папки. Это объяснение проверяемых механизмов, а не обещание абсолютной безопасности или превосходства над любым другим загрузчиком.

## Получить доступные данные, не застревая на одном файле

Проблемный ответ сервера не должен занимать всю очередь. Получение ссылок и передача файлов используют отдельные ограниченные очереди: пока одни файлы скачиваются, для других готовятся ссылки. Один общий лимит соединений включает части всех файлов, поэтому настройка 20 не означает 20 файлов по 8 соединений каждому. Это ограничивает число запросов и потребление ресурсов.

Два таймаута отвечают за разные этапы: ответ на запрос ссылки и отсутствие сетевых данных файла. Ожидание места в очереди, чтение карты и локальная запись не расходуют сетевой бюджет. Нет ограничения, заставляющего прервать долгую загрузку, пока данные поступают.

После реального прогресса допускаются два дополнительных сетевых повтора с ожиданием на 2 секунды больше. Без новых данных повторная цепочка заканчивается; HTTP-ошибка, ошибка записи и плохой хеш её не запускают. Файл уступает очередь другим. Рабочие ссылки повторно используются в памяти серии после подтверждения байтами; отказ приводит к новой ссылке на следующем проходе, а не бесконечному обновлению внутри одного задания.

## Бережно обращаться с API и HDD

HTTP 429 и подходящие временные ошибки включают общий ограничитель API с учётом Retry-After. Он сохраняет состояние между автоматическими проходами, временно увеличивает интервал и постепенно восстанавливает скорость. Готовые скачивания продолжаются. Номинальный выбранный интервал не гарантирует, что сервер не ограничит запросы.

На NTFS диапазоны пишутся независимыми потоками сразу в один sparse-файл. Нет финального чтения всех частей и записи второй полной копии ради сборки. Карта фиксирует SHA-256 участков; сначала сбрасываются данные, потом подтверждающая запись. Контрольная точка — 32 МиБ или 15 секунд на поток, а также окончание попытки. Это частота фиксации, а не обязательная пауза.

После сбоя доверяем проверенным участкам карты, а не выделенной длине файла. Восстановление требует чтения сохранённых байтов, хеширование тратит CPU, flush может задержать запись. Параллельные записи делят HDD; 8 потоков не обязательно быстрее 1–2. При отсутствии sparse остаётся прежний формат. Старые части удаляются после переноса и проверки новой карты.

## Разные проверки отвечают на разные вопросы

| Механизм | Что даёт | Чего не доказывает |
|---|---|---|
| Размер | Быстро отсеивает неполную или другую копию | Одинаковость содержимого |
| Облачный MD5, либо SHA-256 без MD5 | Сверяет целый файл с доступным облачным хешем | При MD5 это контроль целостности, не доказательство подлинности против атак |
| Локальный SHA-256 карты | Проверяет сохранённые участки перед докачкой | Совпадение с облаком без его хеша |
| Быстрая история | Избегает повторного чтения неизменившейся готовой копии | Новую полную проверку содержимого сейчас |
| Полный режим | Заново читает и проверяет доступный хеш | Проверку отсутствующего облачного хеша |

SHA-256 не используется для обхода несовпавшего MD5. Без обоих облачных хешей загрузка разрешена, но результат честно помечен как проверенный только по размеру.

## Прежняя копия не должна исчезнуть при неудачной замене

Сначала скачивается и проверяется новая временная копия. Затем прежняя сохраняется в папке прежних файлов или ошибок проверки, с подпапками и уникальным именем. Неудача сохранения запрещает замену. Новая плохая копия тоже сохраняется. Журнал намерения позволяет восстановить прерванные перемещения; нерешённая операция защищает затронутый путь.

Блокировка ошибки привязана к версии облачного файла и контексту истории. Пересканирование и удаление ошибочной копии не создают бесконечные дубли. Изменившаяся облачная версия разрешает новую попытку. Для неизменившейся версии есть явный ручной однопроходный режим. Не удаляйте историю, если хотите сохранить эти записи. Конфликт служебного имени с другим облачным назначением вызывает безопасный отказ затронутой загрузки.

Единственный движок выполняет API-загрузки в выбранную локальную папку. Код Cloud Files, поиска и перезапуска официального клиента удалён. Старые поля настроек и строки Desktop сохраняют совместимость чтения; история клиента не переносится в историю API. Для папки назначения по-прежнему запрещены облачные заглушки и точки перенаправления.

## Полнота списка и удобство продолжения

Сохранённый список экономит REST-запросы и время перед следующими попытками. Обновление списка ищет изменения в облаке. Это два намеренно разных режима.

Незавершённая папка после перерыва читается с первой страницы; уже найденные пути отсекают дубли. Завершённые папки остаются в сохранённом списке. Новые файлы в них обнаруживаются при полном обновлении списка. Offset не является устойчивым курсором: постоянно меняющийся Диск нельзя объявлять полным снимком. Для финальной сверки нужен свежий список, желательно при отсутствии изменений в облаке.

Дерево папок, фильтры, журнал, история проходов и CSV позволяют увидеть готовые, проблемные и сохранённые копии. Настройки соединений, потоков, интервала API, таймаутов, повторов и способа загрузки позволяют подстроиться под сеть, HDD и задачу. Меняйте один параметр и сравнивайте объём успешной загрузки, а не только время прохода.

## Какие распространённые ошибки подхода здесь учитываются

| Риск в загрузчике | Механизм проекта |
|---|---|
| Удалить прежний файл до получения замены | Новая копия сначала; архивирование до замены |
| Считать выделенную длину скачанным объёмом | Подтверждённая карта диапазонов |
| Склеить части разных облачных версий | Проверка метаданных начатого файла и идентичности карты |
| Повторять плохой файл бесконечно | Лимиты сетевых повторов и запись ошибки версии |
| Принять размер за доказанный хеш | Раздельный уровень подтверждения |
| Считать HashSet гарантией полного списка | Перечитывание прерванной папки и явное обновление списка |
| Передать OAuth на storage-хост при скачивании | Раздельные HTTP-клиенты; API без переноса авторизации через redirect |
| Выдать больше потоков за гарантированное ускорение | Общие лимиты и рекомендации для HDD |

Таблица описывает классы рисков. Она не приписывает ошибки конкретным сторонним проектам без проверки их текущего кода.

## Открытый код и границы приватности

API-путь не требует публикации файлов или промежуточного сервиса автора. Сохранённый токен защищён Windows DPAPI; файлы, отчёты и история остаются обычными локальными данными. Проверка обновлений обращается к GitHub. Открытый исходный код позволяет проверить реализацию и собрать её самостоятельно, но не гарантирует безопасность чужого EXE или заражённого компьютера. Публичные ссылки, cookies и токен нельзя отдавать непроверенным сайтам. После бэкапа отзовите разрешение в Яндекс ID.

Физическое повреждение HDD, отключение с игнорированием flush контроллером, отсутствие облачного хеша и изменения списка во время обхода остаются отдельными ограничениями. [TESTING.md](TESTING.md) отделяет проверенные сценарии от этих границ.

## История без повторного чтения всего журнала

Компактный history.latest хранит последние записи. Контрольная сумма индекса и совпадение пути, длины и времени изменения журнала определяют пригодность кеша; иначе читается исходный history.jsonl. Журнал с избыточными попытками безопасно сокращается; индекс не заменяет проверку файлов. Быстрый режим сохраняет проверку версии, размера и локальной даты; полный режим не использует старое подтверждение после выявленного несовпадения хеша.

Размер из API должен быть неотрицательным целым числом: отсутствие поля не равнозначно пустому файлу. Списки старого формата поддерживаются; неизвестный нулевой размер уточняется до принятия результата.

## Режимы, назначения и сохранение состояния

Пять режимов определяют очередь отдельно от обновления списка. «Ошибки загрузки» требуют совпадения версии; перед загрузкой метаданные проверяются снова. Изменившаяся версия исключается с сохранением прежней записи ошибки, включая аварийное завершение прохода. Полная проверка переходит к недокачанным на автоповторе. Несовпадение хеша разрешает один проход на ручной запуск; следующий ручной запуск остаётся возможным, автоматический следующий проход запрещён.

Инвентаризация сохраняет назначения локальных путей отдельно от текущих страниц обхода. Это удерживает владельцев имён при обновлении и прерывании сканирования. Файлы, папки и служебные артефакты резервируют пути; неоднозначный конфликт блокирует затронутые загрузки до ремонта или записи. Дополнительная карта назначений увеличивает размер инвентаризации; переработка хранения больших каталогов вынесена в отдельную задачу.

Настройки и DPAPI-токен записываются через временный файл в той же папке, flush и атомарную замену. Валидные настройки имеют резервную копию; повреждённый основной файл не заменяет её. Отказ записи отображается в интерфейсе и запрещает старт с несохранёнными настройками. Токен не получает plaintext-резервную копию.

Хеширование копий до записи намерения перемещения допускает остановку. После устойчивой записи намерения перемещение завершается без новой точки отмены, чтобы сохранить восстановимость. Stop в этой фазе может подождать. Подробные границы и результаты приведены в отчётах стабилизации в [TESTING.md](TESTING.md).
