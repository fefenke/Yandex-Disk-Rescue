# Руководство

ВАЖНО: файлы безлимитной автозагрузки фото и видео НЕ учитываются и НЕ скачиваются. Поддерживается только обычный раздел «Файлы».

ПЕРВЫЙ ЗАПУСК
Распакуйте ZIP целиком в постоянную папку и запустите YandexDiskRescue.exe. Приложение всегда открывает «Настройки». Выберите один из двух способов, укажите обязательные поля и нажмите «Начать проход» сверху. Во время сканирования, загрузки и пауз автоповтора параметры заблокированы. Стоп завершает текущие запросы и всю серию повторов.

ЧЕРЕЗ API
Официальный клиент Диска не нужен. Перейдите по OAuth-ссылке в настройках, авторизуйтесь в нужном аккаунте Яндекса, получите токен и вставьте его в приложение. Укажите обычную локальную папку сохранения. Облачный путь disk:/ означает весь Диск, disk:/Фото — выбранную облачную папку. Сохраняется структура подпапок. API работает без перезапусков клиента и поэтому может быть быстрее, но скорость и доступность файлов зависят от ответов Яндекса.

ЧЕРЕЗ КЛИЕНТ ДИСКА
Установите официальный клиент, войдите в аккаунт и дождитесь окончания синхронизации. Выберите его локальную папку Диска. Вводить OAuth-токен в эту программу не требуется. Загрузкой управляют Windows и клиент; приложение запрашивает получение файлов и отслеживает результат. При ошибках синхронизации клиент может перезапускаться. Докачка через HTTP Range относится только к API.

СПИСОК API И РЕЖИМ ПРОХОДА — РАЗНЫЕ НАСТРОЙКИ
По умолчанию используется сохранённый список, без повторного обхода облака. Если списка нет, он будет получен; незавершённое сканирование продолжается с сохранённой позиции. «Обновить список с Диска» нужно для новых, изменённых или удалённых облачных файлов. Обновление списка не означает принудительное повторное скачивание всех файлов.

РЕЖИМЫ ПРОХОДА
• Продолжить незавершённый проход: ещё не обработанные файлы и попытки, прерванные пользователем. Ранее завершённые ошибки пропускаются.
• Повторить ошибки сервера / синхронизации: файлы с записанными ошибками этого типа.
• Повторить таймауты и сбои: файлы без прогресса, оборванные и другие неуспешные загрузки; сюда входят частичные загрузки.
• Повторить все нескачанные: все файлы, для которых нет корректной готовой локальной копии, включая непроверенные и проблемные. Рекомендуемый обычный режим.
• Начать проход с нуля: пройти весь список с начала с повторной проверкой локальных файлов. Корректные готовые копии не скачиваются заново.
• Докачать начатые файлы · API: только непустые .ydr-part. Без автоповтора выполняется один проход; с автоповтором повторяется эта же очередь.

БЕСКОНЕЧНЫЕ ПРОХОДЫ
«Бесконечные проходы» запускает последующие проходы ошибок и сбоев с паузой 30 секунд. Обычный исходный режим после завершения сменяется повтором проблемных файлов; обновлять облачный список каждый раз программа не будет. Режим докачки сохраняется. Серия прекращается по Стоп, при отсутствии подходящих файлов или при ошибке, требующей вмешательства.
ДВА НЕЗАВИСИМЫХ ТАЙМАУТА В API
«Ожидание ссылки, сек» — сколько ждать ответ API со ссылкой на файл после отправки запроса. По умолчанию 3 секунды. Очередь и выбранный интервал между запусками запросов не расходуют этот таймаут. Если ответ не пришёл вовремя, файл остаётся для следующего прохода.
«Без данных файла, сек» — сколько ждать ответ на скачивание, а затем новую порцию данных. По умолчанию 3 секунды. Отсчёт начинается только при запуске скачивания, сбрасывается при получении заголовков ответа и каждой новой порции данных. Очередь готовых ссылок не расходует это время. Пока данные поступают, файл может скачиваться дольше установленного значения. Короткий предел способен прервать медленную рабочую загрузку. Через официальный клиент это поле задаёт предел отсутствия прогресса получения файла; ожидание ссылки к этому режиму не относится.
Оба поля можно менять от 1 до 60 секунд. Это разные этапы, а не общий бюджет на файл: при 3 + 3 получение ссылки имеет свои 3 секунды после отправки, затем скачивание — свои 3 секунды без данных.

ПАРАЛЛЕЛЬНАЯ РАБОТА
По умолчанию до 7 запросов ссылок и до 20 скачиваний работают одновременно и независимо: пока одни файлы скачиваются, для следующих уже получаются ссылки. Это верхние пределы, а не гарантированное число передач. Готовые ссылки ждут свободного места в ограниченной очереди. Интервал запросов API по умолчанию — 50 мс.
По умолчанию включены бесконечные проходы с постоянными значениями 3 + 3 секунды, без автоматического увеличения. Стоп отменяет всю серию. Вручную выбранные значения сохраняются. При переходе на новую схему настройки один раз устанавливаются в 3 + 3, бесконечные проходы включены; история, список файлов и токен сохраняются.
«Увеличивать ожидание до 5 сек» по умолчанию выключено и действует только с автоповтором. Увеличивается только ожидание данных файла; таймаут ссылки не меняется. Каждые два завершённых непустых прохода добавляют 2 секунды, максимум до 5: 1,1,3,3,5 или 3,3,5. Значение от 5 секунд не уменьшается. Новая серия начинается с исходного значения. Ошибки подключения, незавершённые сканы и пустые проходы не увеличивают счётчик.
Временные ошибки соединения и сканирования API повторяются отдельно, с сохранением папки и страницы: первая попытка сразу, затем паузы 1, 2, до 5 секунд и учёт Retry-After сервера. Это не таймаут скачивания. Неверный токен и запрет доступа требуют исправления настроек.

ПАРАЛЛЕЛЬНОСТЬ: ЧТО МЕНЯЮТ ДВА ПОЛЯ
«Запросов ссылок» — сколько задач одновременно запрашивают у API ссылки на следующие файлы. По умолчанию 7, можно выбрать от 1 до 30. Это количество задач в работе, а не число запросов в секунду. Увеличение помогает, если скачивания простаивают в ожидании ссылок; уменьшение стоит попробовать при росте таймаутов ссылки, сетевых сбоев или ответах 429. Больше запросов не гарантируют больше успешных файлов.
«Скачиваний» — сколько файлов одновременно могут ожидать ответ сервера или получать данные по уже полученным ссылкам. По умолчанию 20, можно выбрать от 1 до 30. Пока часть файлов ждёт сервер, другие могут скачиваться. При таймауте место освобождается для следующего файла. Если готовых ссылок мало, заняты будут не все места.
7 + 20 — оптимальный баланс по нашим тестам и начальная рекомендация, а не лимит Яндекса или универсальный оптимум для любого подключения. Можно поставить 30 + 30. Верхний предел 30 в каждом поле установлен программой для ограничения нагрузки на соединения и память. Очередь остаётся ограниченной и не создаёт задачу на каждый файл сразу.
На медленном интернете попробуйте уменьшить число скачиваний, например до 5–10: файлы делят общую скорость канала, и дополнительные потоки не увеличивают её. Если скорость уже близка к скорости вашего подключения, увеличение количества скачиваний обычно не ускоряет общий результат. Если канал простаивает из-за ожидания ответов, увеличение может помочь. Для крупных файлов несколько передач могут заполнить канал, для множества мелких важнее скорость получения ссылок.
Меняйте один параметр за раз и сравнивайте несколько проходов при одинаковых таймаутах: сколько файлов и данных действительно скачалось и за какое время. Быстрый проход с большим количеством отказов не обязательно лучше. Все пять параметров загрузки сохраняются, во время прохода и пауз автоповтора менять их нельзя. Параллельность и ожидание ссылки относятся только к API; через официальный клиент количеством загрузок управляют Windows и клиент.

ИНТЕРВАЛ ЗАПУСКА ЗАПРОСОВ
«Интервал запросов API, мс» — время между запусками запросов API. Диапазон 25–1000 мс, по умолчанию 50 мс. При 25 мс получается примерно до 40 запусков в секунду, при 50 — до 20, при 100 — до 10, при 200 — до 5, при 1000 — до одного. Ответа предыдущего запроса ждать не нужно: несколько задач могут одновременно ожидать ответ.
Уменьшайте интервал, если хотите повысить частоту запусков и сравнить результат. Увеличивайте, если появляются ограничения частоты, ответы 429 или нестабильность API. Меньший интервал не гарантирует лучшую скорость или успешность. Ожидание очереди и выбранного интервала не расходует таймаут получения ссылки. Значение сохраняется и блокируется во время работы.
В пункте 2.2 официальных условий API Яндекс Диска указан предел 40 запросов в секунду: https://yandex.ru/legal/disk_api/ru/ . Это ограничение частоты, а не числа одновременно ожидающих задач. Начальные 50 мс оставляют запас до указанного предела.

ДОКАЧКА И ЦЕЛОСТНОСТЬ
В API непустой .ydr-part дописывается через HTTP Range, если сервер принимает нужный диапазон и версия файла совпадает. Если сервер возвращает весь файл, загрузка начинается заново. Перед завершением проверяются размер и MD5, если API предоставил его. Только после проверки временный файл становится готовым. Проверка одного размера слабее проверки MD5; повреждение оригинала в облаке программа не исправляет.
HTTP 5xx относится к ошибкам сервера. IOException означает сбой чтения/записи или соединения и не доказывает серверную ошибку. Тип и код сбоя видны в журнале. Частичный файл может сохраняться даже после следующей попытки с нулём новых байтов.

СВЕРКА ПЕРЕД ПРОХОДОМ
Перед скачиванием программа сверяет историю и локальные файлы. Вверху показаны количество проверенных файлов и общий прогресс. Если требуется MD5, видны процент, прочитанные мегабайты, время проверки и имя текущего файла. Крупные видео могут проверяться долго; время продолжает обновляться и во время ожидания чтения диска. На этой стадии счётчик готовых файлов промежуточный. История конкретной копии приложения находится рядом с ней: запуск другой копии с более старой историей может вызвать повторную проверку уже имеющихся файлов.

ИНТЕРФЕЙС И СТАТИСТИКА
«Обзор» показывает только категории с файлами. «Файлы и папки» — дерево, количество готовых копий и процент с учётом подпапок. Справа содержимое выбранной папки; поиск и фильтр нескачанных действуют внутри неё. Длинные имена доступны в подсказках; ширину колонок и разделителя можно менять, горизонтальная прокрутка появляется при необходимости.
Двойной щелчок по скачанному файлу открывает его стандартной программой, по папке справа — показывает содержимое. В контекстном меню файла есть открытие и показ в Проводнике; недокачанный файл нельзя открыть как готовый. У папки есть открытие в Проводнике. Для отсутствующего локального объекта перейти в его расположение пока невозможно.
Дерево и история читаются локально, без дополнительного запроса к Яндексу. Первое чтение большой истории занимает время и выполняется в фоне. Статистика опирается на сохранённые результаты и не является новой полной проверкой MD5. Обновление списка показывает изменения облака.
«Скачано всего» — готовые файлы, «за проход» — новые успехи текущего прохода. «Осталось» относится ко всему списку, знаменатель обработки — к выбранному режиму. Журнал имеет поиск и фильтры «Все события», «Успешные», «Ошибки», без автопрокрутки. «Проходы» хранит итоги каждой попытки; подробные отчёты находятся в data.

ОБНОВЛЕНИЯ
Галка «Проверять обновления автоматически» включает проверку публичных выпусков GitHub при запуске и каждые 6 часов. Снятая галка отключает фоновые проверки, выбор сохраняется. «Проверить обновления» и «Обновить» доступны вручную. Установка предлагается только вне прохода и после согласия пользователя.
Программа скачивает ZIP своей разрядности, проверяет SHA-256 из GitHub, закрывается, заменяет только программные файлы и перезапускается. Папка data с историей, списком, настройками и зашифрованным токеном не заменяется. При сбое замены предусмотрен откат. Если GitHub недоступен, скачивание файлов продолжает работать. Версии без обновлятора нужно один раз обновить вручную.
Версия 1.0.2 поддерживает обновление из приложения с сохранением настроек и истории.

БЕЗОПАСНОСТЬ И ОГРАНИЧЕНИЯ
Токен хранится локально через Windows DPAPI с привязкой к вашей учётной записи Windows. Для работы он расшифровывается в памяти; шифрование хранения не заменяет доверие к программе. Не отправляйте токен другим людям; когда доступ больше не нужен, отзовите его в Яндекс ID. Свою папку data не публикуйте. При обновлении сохраняйте её, не переносите историю поверх работающего приложения.
Проект независимый и неофициальный, не связан с Яндексом. Он не исправляет серверные ошибки, не восстанавливает удалённые данные и не гарантирует скачивание каждого файла. Безлимитная автозагрузка не поддерживается.


СООБЩЕНИЯ ОБ ОШИБКАХ
Download link request timed out. — API не вернул ссылку за время «Ожидание ссылки, сек»; скачивание в этой попытке ещё не началось. Таймаут данных означает, что ответ на скачивание или новая порция данных не поступили вовремя. Сам по себе таймаут не означает ошибку 500 или повреждение файла.
HTTP 429 — слишком много запросов: увеличьте интервал запросов API и повторите позже. HTTP 503 — сервис временно недоступен. HTTP 500 — внутренняя ошибка сервера. Повтор может помочь при временном сбое, но не гарантирует доступность файла.
В бесконечном режиме выбранные таймауты сохраняются между проходами без автоматического увеличения.
