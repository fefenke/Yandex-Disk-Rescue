# Руководство

ВАЖНО: файлы безлимитной автозагрузки фото и видео НЕ учитываются и НЕ скачиваются. Поддерживается только обычный раздел «Файлы».

ПЕРВЫЙ ЗАПУСК
Распакуйте ZIP целиком в постоянную папку и запустите YandexDiskRescue.exe. Приложение всегда открывает «Настройки». Выберите один из двух способов, укажите обязательные поля и нажмите «Начать проход» сверху. Во время сканирования, загрузки и пауз автоповтора параметры заблокированы. Стоп завершает текущие запросы и всю серию повторов.

ЧЕРЕЗ API
Официальный клиент Диска не нужен. Перейдите по OAuth-ссылке в настройках, авторизуйтесь в нужном аккаунте Яндекса, получите токен и вставьте его в приложение. Укажите обычную локальную папку сохранения. Облачный путь disk:/ означает весь Диск, disk:/Фото — выбранную облачную папку. Сохраняется структура подпапок. API работает без перезапусков клиента и поэтому может быть быстрее, но скорость и доступность файлов зависят от ответов Яндекса.

ЧЕРЕЗ КЛИЕНТ ДИСКА
Установите официальный клиент, войдите в аккаунт и дождитесь окончания синхронизации. Выберите его локальную папку Диска. Вводить OAuth-токен в эту программу не требуется. Загрузкой управляют Windows и клиент; приложение запрашивает получение файлов и отслеживает результат. При ошибках синхронизации клиент может перезапускаться. Докачка через HTTP Range относится только к API.

СПИСОК API И РЕЖИМ ПРОХОДА — РАЗНЫЕ НАСТРОЙКИ
По умолчанию используется сохранённый список, без повторного обхода облака. Если списка нет, он будет получен; незавершённое сканирование продолжается с сохранённой позиции. «Обновить список с Диска» нужно для новых, изменённых или удалённых облачных файлов. Обновление списка не означает принудительное повторное скачивание всех файлов.

РЕЖИМЫ ПРОХОДА
• Продолжить незавершённый проход: ещё не обработанные файлы и попытки, прерванные пользователем. Ранее завершённые ошибки пропускаются.
• Повторить ошибки сервера / синхронизации: файлы с записанными ошибками этого типа.
• Повторить таймауты и сбои: файлы без прогресса, оборванные и другие неуспешные загрузки; сюда входят частичные загрузки.
• Повторить все нескачанные: все файлы, для которых нет корректной готовой локальной копии, включая непроверенные и проблемные. Рекомендуемый обычный режим.
• Начать проход с нуля: пройти весь список с начала с повторной проверкой локальных файлов. Корректные готовые копии не скачиваются заново.
• Докачать начатые файлы · API: только непустые .ydr-part. Без автоповтора выполняется один проход; с автоповтором повторяется эта же очередь.

АВТОПОВТОР И ОЖИДАНИЕ
«Повторять проблемные файлы» запускает последующие проходы ошибок и сбоев с паузой 30 секунд. Обычный исходный режим после завершения сменяется повтором проблемных файлов; обновлять облачный список каждый раз программа не будет. Режим докачки сохраняется. Серия прекращается по Стоп, при отсутствии подходящих файлов или при ошибке, требующей вмешательства.
«Без прогресса, сек» — допустимая пауза без новых данных, а не общее время скачивания. В API начальное ожидание также охватывает получение ссылки и первого ответа. Новые данные сбрасывают отсчёт. Для быстрого прохода можно начать с 1 секунды; при повторах таймаутов попробовать 3–5 секунд. Короткий предел способен прервать медленную рабочую загрузку.
«Увеличивать ожидание до 5 сек» действует только с автоповтором. Каждые два завершённых непустых прохода добавляют 2 секунды, максимум до 5: 1,1,3,3,5 или 3,3,5. Значение от 5 секунд не уменьшается. Новая серия начинается с исходного значения. Ошибки подключения, незавершённые сканы и пустые проходы не увеличивают счётчик.
Временные ошибки соединения и сканирования API повторяются отдельно, с сохранением папки и страницы: первая попытка сразу, затем паузы 1, 2, до 5 секунд и учёт Retry-After сервера. Это не таймаут скачивания. Неверный токен и запрет доступа требуют исправления настроек.

ДОКАЧКА И ЦЕЛОСТНОСТЬ
В API непустой .ydr-part дописывается через HTTP Range, если сервер принимает нужный диапазон и версия файла совпадает. Если сервер возвращает весь файл, загрузка начинается заново. Перед завершением проверяются размер и MD5, если API предоставил его. Только после проверки временный файл становится готовым. Проверка одного размера слабее проверки MD5; повреждение оригинала в облаке программа не исправляет.
HTTP 5xx относится к ошибкам сервера. IOException означает сбой чтения/записи или соединения и не доказывает серверную ошибку. Тип и код сбоя видны в журнале. Частичный файл может сохраняться даже после следующей попытки с нулём новых байтов.

ИНТЕРФЕЙС И СТАТИСТИКА
«Обзор» показывает только категории с файлами. «Файлы и папки» — дерево, количество готовых копий и процент с учётом подпапок. Справа содержимое выбранной папки; поиск и фильтр нескачанных действуют внутри неё. Длинные имена доступны в подсказках; ширину колонок и разделителя можно менять, горизонтальная прокрутка появляется при необходимости.
Двойной щелчок по скачанному файлу открывает его стандартной программой, по папке справа — показывает содержимое. В контекстном меню файла есть открытие и показ в Проводнике; недокачанный файл нельзя открыть как готовый. У папки есть открытие в Проводнике. Для отсутствующего локального объекта перейти в его расположение пока невозможно.
Дерево и история читаются локально, без дополнительного запроса к Яндексу. Первое чтение большой истории занимает время и выполняется в фоне. Статистика опирается на сохранённые результаты и не является новой полной проверкой MD5. Обновление списка показывает изменения облака.
«Скачано всего» — готовые файлы, «за проход» — новые успехи текущего прохода. «Осталось» относится ко всему списку, знаменатель обработки — к выбранному режиму. Журнал имеет поиск и фильтры «Все события», «Успешные», «Ошибки», без автопрокрутки. «Проходы» хранит итоги каждой попытки; подробные отчёты находятся в data.

ОБНОВЛЕНИЯ
Галка «Проверять обновления автоматически» включает проверку публичных выпусков GitHub при запуске и каждые 6 часов. Снятая галка отключает фоновые проверки, выбор сохраняется. «Проверить обновления» и «Обновить» доступны вручную. Установка предлагается только вне прохода и после согласия пользователя.
Программа скачивает ZIP своей разрядности, проверяет SHA-256 из GitHub, закрывается, заменяет только программные файлы и перезапускается. Папка data с историей, списком, настройками и зашифрованным токеном не заменяется. При сбое замены предусмотрен откат. Если GitHub недоступен, скачивание файлов продолжает работать. Версии без обновлятора нужно один раз обновить вручную.
0.9.8 и 0.9.9 используются для проверки реального перехода между выпусками. 1.0.0 пока не опубликована.

БЕЗОПАСНОСТЬ И ОГРАНИЧЕНИЯ
Токен хранится локально через Windows DPAPI с привязкой к вашей учётной записи Windows. Для работы он расшифровывается в памяти; шифрование хранения не заменяет доверие к программе. Не отправляйте токен другим людям; когда доступ больше не нужен, отзовите его в Яндекс ID. Свою папку data не публикуйте. При обновлении сохраняйте её, не переносите историю поверх работающего приложения.
Проект независимый и неофициальный, не связан с Яндексом. Он не исправляет серверные ошибки, не восстанавливает удалённые данные и не гарантирует скачивание каждого файла. Безлимитная автозагрузка не поддерживается.
